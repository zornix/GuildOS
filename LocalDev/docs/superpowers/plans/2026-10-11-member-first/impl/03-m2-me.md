## T5 — Change password with an email code (#123, added 2026-10-12)

User decision: a signed-in member changes their password with the current password **and** a code sent by email. The old password is replaced only after the code is confirmed; an unfinished flow changes nothing. Forgot password is the separate M0 flow.

- [ ] `migrations/0226_password_change_requests.sql`: table `password_change_requests` (id, chapter_id, member_id, new_password_hash, code_hash, expires_at, attempts, used_at, created_at), one open row per member (a new request replaces the old one); widen `message_outbox.event_type` with `PASSWORD_CHANGE_CODE` using the dynamic rebuild pattern from `0160`.
- [ ] Failing tests `tests/auth/test_password_change.py`: wrong current password → 403, nothing stored; right one → 202, an outbox row `PASSWORD_CHANGE_CODE` for the member, password still unchanged (old logs in, new does not); confirm with the right code → 200, new logs in, old does not, token epoch bumped; wrong code → 403, and after the limit the request is dead; expired request → 410 and nothing changed; a second request replaces the first (first code no longer works); both routes rate-limited like login; a `pwd_setup` token is refused.
- [ ] `POST /api/auth/password-change` {current_password, new_password} and `POST /api/auth/password-change/confirm` {code}, using `get_db().transaction()`; reuse `_check_secret`, `_enforce_rate_limit` and `_record_attempt`. The email template goes next to `RESET_CODE` in `api/platform/message_templates.py`.
- [ ] Frontend: Profile "Change password" → "Enter the code we emailed you" step; pure validator in `lib/profile.ts`; toast only after the server answers. Test: the form renders both steps from props.
- [ ] Checkpoint: `python3 -m pytest tests/auth -q` and `npm test && npm run lint`.

## Risks

- The password-change outbox type widens the `message_outbox.event_type` CHECK; use the dynamic rebuild pattern (README rule 4.5).
- `member_class` validation must match in Pydantic, SQL and `lib/profile.ts` — one regex, copied verbatim, with a test on each side.
- The redeem-scope check touches every authenticated route; keep it to one claim check and test one unrelated route.
