ESTABLISHED RUNTIME FACTS (verified by the lead auditor; rely on them and cite them):
1. One DB path: api/platform/postgres.py PostgresClient — a PostgREST-shaped query builder over psycopg2 with a per-process ThreadedConnectionPool(1,10), connecting with DATABASE_URL (Supabase session pooler, role postgres.<ref>, which bypasses RLS). EVERY QueryBuilder.execute() and _RpcBuilder.execute() sets conn.autocommit = True: each table operation is its own transaction; the ONLY atomic multi-row operations are the plpgsql RPCs called via sb.rpc(...).execute() / api/platform/rpc.py:call_rpc.
2. RLS is enabled on 42 of 55 tables but is NOT enforced at runtime (ADR-0002 admits it is unexercised and untested; the policies' helper functions read request.jwt.claims which this path never sets). Tables WITHOUT RLS at all: attendance, chapters, event_roles, event_tasks, event_template_roles, event_template_tasks, event_templates, events, excuses, fines, members, message_outbox, post_event_reports. No table has FORCE ROW LEVEL SECURITY. Tenant isolation rests entirely on Python query filters (.eq('chapter_id', user['chapter_id'])) and on RPC bodies validating each referenced row's chapter_id.
3. SELECT results are raw psycopg2 types (uuid.UUID objects, Decimal, datetime.date/time/datetime) — _exec_select never calls _serialize; INSERT/UPDATE/UPSERT 'RETURNING *' rows DO go through _serialize (UUID→str, Decimal→float, date/time/datetime→isoformat string). RPC results are whatever the function returns (usually jsonb → dict with string ids). So the same id can be a UUID object or a str depending on where it came from, and 'a == b' between them is False.
4. Column/identifier names in the query builder are interpolated into SQL unescaped (select columns, .eq/.in_ column names, .order column, on_conflict); values are parameterized. RPC function/param names are regex-validated.
5. Auth: api/auth/api/auth.py mints HS256 JWTs (sub=member id, iss/aud='guildos', exp 7 days, 'ver'=members.token_version); api/platform/postgres.py _LocalAuth.get_user verifies alg/aud/iss and requires exp/sub; api/dependencies.py get_current_user loads the ACTIVE member row with chapters join and rejects a stale 'ver'. No refresh tokens; logout is client-side only. Rate limiting for login/redeem counts failed rows in login_attempts per email (10/15min) and per rightmost-trusted X-Forwarded-For IP (20/15min). Chapter self-signup POST /api/chapters is unauthenticated with an in-process rate limiter, or authenticated by PLATFORM_SECRET. Cron routes require CRON_SECRET. Twilio webhook verifies X-Twilio-Signature with BASE_URL.
6. Authorization: api/rbac/auth.py require_permission(*keys) (ANY-of) → api/rbac/services/permissions.py get_member_permissions (2 queries per call: member_roles then role_permissions; unioned with the legacy members.role column via core/policy.py LEGACY_ROLE_COMPAT). has_permission adds ownership scoping only for tasks:complete→tasks:review. Some routes call has_permission inline instead of the dependency. The frontend stores the JWT in localStorage and gates UI on GET /api/rbac/me/permissions.
